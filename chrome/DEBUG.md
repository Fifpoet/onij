# 🔧 音乐信息提取器调试指南

## 问题诊断

如果插件仍然显示URL而不是音乐信息，请按以下步骤进行调试：

### 1. 检查插件是否正确加载

1. 打开Chrome扩展管理页面 (`chrome://extensions/`)
2. 确保"音乐信息提取器"插件已启用
3. 点击"详细信息"查看是否有错误

### 2. 检查Content Script注入

1. 访问 `https://zm.i9mr.com` 网站
2. 打开开发者工具 (F12)
3. 在控制台中查看是否有以下日志：
   - `音乐信息提取器 Content Script 已启动`
   - `🎵 拦截到音乐详情API请求: ...`

### 3. 检查API拦截

1. 在音乐网站页面打开开发者工具
2. 访问一个音乐详情页面
3. 查看控制台是否有以下日志：
   - `🔍 开始解析API响应: ...`
   - `📄 API响应数据: ...`
   - `🎼 开始提取音乐信息...`
   - `✅ 提取到音乐信息: ...`

### 4. 检查Background Script

1. 在扩展管理页面点击"检查视图" -> "Service Worker"
2. 查看是否有以下日志：
   - `音乐信息提取器已启动，正在监听请求...`
   - `🎵 Background收到音乐信息: ...`
   - `💾 音乐信息已保存到存储: ...`

### 5. 检查存储数据

1. 打开插件弹窗
2. 右键点击插件图标 -> "检查弹出内容"
3. 在控制台中运行：
   ```javascript
   chrome.storage.local.get(['musicRequests'], (result) => {
       console.log('存储的请求:', result.musicRequests);
   });
   ```

### 6. 使用调试测试页面

1. 打开 `debug-test.html` 文件
2. 点击测试按钮
3. 查看日志输出

## 常见问题

### 问题1: Content Script没有注入
**原因**: manifest.json配置问题或网站URL不匹配
**解决**: 检查manifest.json中的matches规则

### 问题2: API响应格式不匹配
**原因**: 实际API响应结构与预期不符
**解决**: 查看控制台中的API响应数据，调整解析逻辑

### 问题3: 音乐信息没有保存
**原因**: Background script消息处理问题
**解决**: 检查Background script的控制台日志

### 问题4: 显示格式不正确
**原因**: Popup渲染逻辑问题
**解决**: 检查popup.js中的renderRequests方法

## 调试步骤

1. **重新加载插件**:
   - 在扩展管理页面点击刷新按钮
   - 或者禁用后重新启用

2. **清除存储数据**:
   - 在插件弹窗中点击"清空"按钮
   - 或者在控制台中运行：
     ```javascript
     chrome.storage.local.clear();
     ```

3. **检查网络请求**:
   - 在开发者工具的Network标签页中
   - 筛选 `/song/detail` 请求
   - 查看响应内容

4. **逐步测试**:
   - 先测试Content Script注入
   - 再测试API拦截
   - 最后测试数据保存和显示

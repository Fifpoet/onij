# feat 方案文档

讨论收口后写这里；实现阶段只维护勾选，不另开一份计划。

- 路径：`docs/feat/<slug>.md`
- `slug`：小写英文/数字/连字符，与口令一致。用户说「做 feat ktv-mic」→ 读 `docs/feat/ktv-mic.md`
- 进行中的讨论**不要**每轮都写文件；只在方案收口时写一次（之后实现者勾选）
- 不要往 `docs/` 根目录丢杂项；产品代码约定仍在 `.cursor/rules/`

## 何时写

方案讨论已齐（目标、范围、非目标清楚），用户说「就这样 / 定了 / 收口」或等价确认。此时：

1. 新建或覆盖对应 `docs/feat/<slug>.md`（用下面模板）
2. 对用户用**固定收口格式**（见文末），不要只丢一句「写好了」

没有文件就说「做 feat xxx」：先补写该 md（从对话提炼），再开工作流。提炼不出范围则回到讨论，不要空开实现。

## 文件模板

```markdown
---
slug: example-slug
title: 中文短标题
status: proposed
---

# <中文短标题>

## 目标

一句话：做成后用户能看到/做到什么。

## 非目标

本轮明确不做的（避免实现时膨胀）。

## 大体方案

- 关键链路 / 数据流（几条 bullet）
- 拟改文件（路径 + 一句话）
- 与现有功能的关系（复用什么、不要动什么）

## 本轮任务

实现者按项做并勾选，不要删条目（做不了就留着并在备注说明）。

- [ ] 任务 1（可验收的一小步）
- [ ] 任务 2

## 相关未做

和本主题有关、但本轮不做。不要勾选成完成；新开 feat 或下次讨论再收口。

- 未做项 A（原因：范围外 / 缺信息 / 依赖未定）
- 未做项 B

## 验证

- 命令：如 `pnpm exec vue-tsc --noEmit` / `go test ./logic/`
- 浏览器：哪条路由、点什么
- 必须人确认：麦克风 / 网易云 / 七牛 等

## 风险

全局样式、App.vue、搜索页、七牛域名、改表 等。没有写「无」。

## 实现备注

实现过程由 implementer 追加（日期 + 做了什么）。讨论收口时留空。
```

`status`：`proposed`（刚收口）→ `in_progress`（开始做）→ `done`（verifier 通过且本轮任务全勾）。相关未做仍在也不要改成 done，保持 `in_progress` 并在收口里写明。

## 谁改这个文件

| 角色 | 允许 |
|------|------|
| 主 Agent（讨论收口） | 创建/重写全文 |
| `planner` | 只读。文件级计划交回主 Agent；主 Agent 可把路径补进「本轮任务」再实现 |
| `implementer` | `status=in_progress`；勾选已完成的「本轮任务」；只在「实现备注」追加。不删「相关未做」，不把范围外需求勾掉 |
| `tester` / `reviewer` / `verifier` | 不改此文件 |
| 主 Agent（工作流收口） | 按验收结果补勾漏项；更新 `status`；把新发现但本轮不做的点追加到「相关未做」 |

## 讨论收口时对用户的固定输出

写完 md 后，主 Agent **原文结构**输出下面这块（可填空，不可省略小节）：

```
方案已收口：feat <slug>
文件：docs/feat/<slug>.md

大体方案
- （3～7 条，能看懂怎么做即可）

本轮要做
- [ ] …
- [ ] …

相关未做
- …（没有则写「无」）

下一步：说「做 feat <slug>」启动工作流。
```
